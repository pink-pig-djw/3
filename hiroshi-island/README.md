# 浩的岛 · Hiroshi's Island

> 沿着溪水，多停留一会儿。

一款以**拍照**和**记忆**为核心的写实治愈系网页游戏（第一章：溪谷）。
浩爷爷留下一台旧相机和一本泡过水的相册，照片花了，只剩他写在每页底下的字。你要在岛上的不同时段，照着那些字把十张照片重新拍回来。每拍对一张，就会解锁一段他和阿夏的往事。

- **美术资产**：全部由 **Blender（bpy）脚本程序化生成**，包括用真实微观几何烘焙的 PBR 贴图、地形、岩石、树木、建筑和小动物。没有使用任何外部素材。
- **实时渲染**：**Three.js**（WebGL2），基于物理的天空和光照，配合一套为写实效果定制的着色器与后期处理。

## 快速开始

```bash
cd hiroshi-island
npm install
npm run dev        # 打开终端里提示的地址（默认 http://localhost:5173）
```

构建静态版本：`npm run build`，产物在 `dist/`，用任何静态服务器托管即可。

### 网页版（单页 / 离线单文件）

```bash
npm run build:web
```

会生成两样东西：

| 产物 | 说明 |
|---|---|
| `dist-web/site/index.html` + `dist-web/site/assets/` | 单页网页版：游戏代码和样式都内联在页面里，资源放在旁边，用相对路径读取。可以直接发布成在线网页（发布到 claude.ai 时页面外层的文档骨架由宿主补上，本地测试用 `dist-web/site/local.html`）。 |
| `dist-web/hiroshi-island-offline.html` | 离线单文件（约 20 MB）：全部资源都打包进一个 HTML，双击就能在浏览器里打开，不需要服务器。 |

网页版和开发版的区别：

- **不需要 WebAssembly**：模型去掉 Draco 压缩，改用 gzip，由浏览器自带的 `DecompressionStream` 解压。在线网页不提供原始二进制文件类型，所以模型和地形数据以 base64 文本（`.gz.b64.txt`）的形式放在页面旁边。
- 三个库（three、postprocessing、n8ao）都打进游戏自己的脚本里，不从 CDN 加载。
- 页面在线更新时会保留当前位置和时段（`window.claude.hot` 快照），刷新后停在暂停界面。

> 推荐使用带独立显卡的桌面浏览器（Chrome / Edge / Firefox）。标题画面可以切换**画质（低 / 中 / 高）**；也可以在地址后加 `?quality=low` 强制使用低画质。手机和平板默认用低画质。

### 玩法

- **十个拍摄目标**分布在 **午后 / 黄金时刻 / 蓝调时刻 / 夜晚** 四个时段，相册里浩写下的字就是提示。
- 照片的判定标准：
  - 拍摄对象在取景框（3:2）内
  - 在画面里足够大
  - 没有被遮挡
  - 落在**景深**范围内（按全画幅相机的物理公式计算：焦距、光圈、对焦距离、弥散圆 0.03mm）
  - 时段正确
- 达到 **两星** 就算拍对，会解锁一段回忆；构图落在**三分线交点**或画面正中可以拿到**三星**。
- 在河边平台的长椅上按 **E** 坐下，时间会推进到下一个时段，并依次解锁。集齐十张后可以随时切换时段。
- 进度（照片、时段、位置）自动保存在浏览器的 `localStorage` 里。

## 资产管线（Blender）

所有资产由 `blender/` 下的脚本生成，可以用 **Blender 5.x** 运行，也可以用 PyPI 上的 **`bpy` 模块** 在后台运行（不需要图形界面）：

```bash
# 方式一：独立 bpy 模块（Python 3.13）
pip install bpy==5.2.2 numpy scipy pillow
python blender/build_all.py                 # 全部重建（约 15 分钟，大部分时间在 Cycles 烘焙）
python blender/build_all.py --skip-textures # 跳过最慢的贴图烘焙
python blender/build_all.py --blend-only    # 只把关卡拼装成 blender/build/island.blend

# 方式二：在 Blender 里运行
blender -b -P blender/build_all.py
```

| 脚本 | 产出 |
|---|---|
| `textures.py` | 10 套可平铺 PBR 贴图（河床卵石、土路、草地、落叶层、岩石、苔藓、树皮、旧木板、灰泥、瓦）。每套都先**建模真实的微观几何**（成千上万的卵石、草叶、落叶），再用 Cycles 从高模烘焙到平面，得到反照率、法线、AO、粗糙度和高度 |
| `water_textures.py` | 顺流方向拉长的水面波纹法线、泡沫图（numpy 频谱合成） |
| `terrain.py` | 513² 高度场：沿溪流挖出河道、外弯陡岸与内弯砾石滩、深潭、小瀑布、涵洞路堤、屋前平台、小路；以及混合权重图、植被密度图和 `layout.json`（树、石头、灌木、蕨类、芦苇、栅栏、灯笼的分布） |
| `rocks.py` | 8 种溪石（圆润溪石、棱角山石、平板踏脚石）：33 万面的高模雕刻后减面，烘焙到一张 2048 图集 |
| `vegetation.py` | 用 Cycles 渲染枝叶卡片图集；用**空间殖民算法**生长 4 种阔叶树（花瓶形榉树、圆冠橡树、细高赤杨、歪脖老树），管径按达·芬奇法则计算，每种带远景 LOD；另有灌木、蕨类、芦苇。顶点里存了风吹参数 |
| `architecture.py` | 石砌拱形涵洞（拱券、拱顶石、压顶石、隧道、桥面铺石）、带檐廊和栏杆的木屋（地基石、柱梁、障子、灰泥墙、歇山顶真实瓦垄）、河边木平台和长椅、石阶、栅栏、灯笼 |
| `creatures.py` | 山女鳟、蜻蜓、河灯、风铃、草帽 |
| `world_spec.py` | 手工设定的关卡数据：溪流走向、涵洞、小屋、小路、开场位置等。**改这里再重跑脚本即可调整关卡** |

脚本最后会用 `npm run optimize`（Draco）压缩模型，并生成 `blender/build/island.blend`：完整拼好的溪谷场景（地形、建筑、所有树和石头），方便在 Blender 里查看或继续编辑。

## 渲染技术（Three.js）

- **天空**：Rayleigh + Mie + 臭氧吸收的单次散射，加上近似的多次散射（日落后被地球阴影挡住的那部分天空也有蓝色天光）。天空先渲染成立方体贴图，再经 PMREM 生成环境光照；太阳和月亮的颜色由大气透射率决定。另有星空、银河和云层。
- **时段**：太阳和月亮的方位驱动一切；曝光根据天空和太阳亮度自动计算，夜晚再叠加人眼在暗处的偏蓝效果（浦肯野效应），灯笼保持暖色。
- **雾**：高度指数雾，加上朝向太阳的散射。
- **地形**：5 层材质按高度混合，陡坡用三平面投影，加大尺度色彩变化和反重复采样；水下有动态焦散，岸边有湿润效果。
- **溪水**：
  - 折射，按水深做 Beer–Lambert 吸收
  - 屏幕空间反射，失败时回退到环境贴图
  - 顺流的流向贴图波纹，接触泡沫和跌水泡沫
  - GGX 高光，形成阳光和月光的闪烁
- **植被**：
  - 草地：环绕相机的草丛实例，每丛 7 片细叶，包含风场、阵风、玩家拨开草叶和背光透射
  - 野花
  - 树木和灌木：CPU 视锥剔除，近处用完整模型、远处用简化版，带三层风吹动画
  - 叶片有透射，阴影支持 alpha 裁剪
- **后期处理**：
  - 水面渲染前先单独渲一遍不透明场景，取颜色和深度给水面用
  - N8AO 环境光遮蔽
  - **物理景深**：弥散圆由焦距、光圈和对焦距离计算，半分辨率黄金角散景
  - 多级 mipmap 泛光，AgX 色调映射，色彩分级、暗角、胶片颗粒，SMAA
- **声音**：全部用 WebAudio 合成，包括溪水（随位置变化的空间声）、风声、树叶、鸟鸣、蝉鸣、夜里的虫鸣、风铃、脚步声（草地 / 木板 / 石头 / 水中各不相同）和快门声。


## 已知限制

- 全部资产都是程序化生成的，近看树叶和石头仍能看出"生成感"；没有用照片扫描素材。
- 植被没有使用 TAA，alpha 裁剪的边缘在低分辨率下会有锯齿。
- 目前只有第一章（溪谷），岛上的其他区域还没有做。
- 手机上的触控操作只在模拟器（Playwright 触屏模拟）里测试过，没有在真机上测过帧率；低端手机可能跑不动。
